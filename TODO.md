# Win Computer Online Web App — Outcomes

- [x] Online access and application login — Users can open the web app through a hosted HTTPS URL and sign in using the configured application authentication. The first Owner account is created only after the secure approval password is configured. Normal customers can self-register with essential information and use their active customer account without Owner approval; Admin, Staff, Accountant, General Worker, Technician, Sales, Marketing and Talent accounts require Owner approval before activation.
- [x] Owner/Admin administration — Exactly one Owner authority can change global brand/settings, users, roles, notices, maintenance mode, data import/restore and other sensitive administration. Admin and Owner can deactivate, restore or remove non-owner accounts; the Owner account cannot be removed. These checks must be enforced server-side, not only by hiding buttons.
- [x] Role and capability management — Owner can create/deactivate users, assign Owner/Admin/Staff/Accountant/General Worker/Technician/Sales/Marketing/Talent/Customer roles or custom capabilities, review permission requests, and approve/reject pending staff/admin/job-role requests.
- [x] Account request and profile workflow — Applicants can provide role, contact information and profile photo; Owner review shows submitted fields/photo, approval creates the account/profile transactionally, rejection records a note, and approved users complete their profile before workspace access. Customers use a separate short self-registration form.
- [x] Online user and device monitoring — Authenticated sessions persist heartbeat and non-secret device class. Owner/Admin can see every active account's online/offline state, online count, role, last seen, device class and how long the user has been offline.
- [x] Professional bilingual interface — Burmese/English labels, Win Computer branding, dark/navy/gold visual system, responsive layout and readable tables remain implemented.
- [x] Business dashboard and daily reports — Dashboard includes recorded business figures plus seven-day titled table/chart for received and pending amounts.
- [x] Receipts and payment status — Authorized users can create sale/service receipts with payment method and received/pending status.
- [x] Void/refund safety — Void/refund actions require approval, reason, status transition and audit entry.
- [x] Catalog and pricing — Admin/Owner can add/manage product categories, products, services and prices; price history and audit information remain retained. Catalog controls and migrations were checked with typecheck, tests and production build.
- [x] Audit and notices — Role/user-targeted bilingual notices, status messages, permission notices and maintenance messages appear in the authenticated Inbox with read acknowledgement.
- [x] Data export/import — Authorized export and Owner-only JSON restore remain implemented.
- [x] Account lifecycle messaging and directory — Deleted accounts are soft-deleted, removed from the visible directory and chat contacts, and a respectful account-status notice is generated. The directory shows profile image, department, job title, role and active status.
- [x] Internal chat — Approved active users can select another user, view a private conversation, send text or compressed image attachments, and trigger a recipient Inbox notice. Deleted accounts are excluded.
- [x] Role welcome/profile card — The welcome workspace is separated into customer and staff/administration audiences, with bilingual messaging and a contact/payment icon row for phone, Viber, Telegram, KBZPay and WavePay. After login, the shell shows the signed-in person’s profile image, role/position and department where available; profile editing persists department.
- [ ] Production readiness and Namecheap handoff — The app has a container build/health path and a clear custom-domain guide. Domain purchase and DNS changes are not performed without registrar/hosting authorization.
- [x] Catalog error isolation — Category, product and service queries load only for the selected catalog tab, so an unavailable hidden table cannot blank the entire catalog screen; retry remains available for the active tab.
- [x] Audit pagination and exact wording — Activity history is displayed 10 records per page with Previous/Next controls. Lifecycle records state who deactivated/removed/restored which account and include the written reason.
- [x] Account archive — Deactivated and removed staff accounts remain in a separate archive with status, date/time and lifecycle reason; soft-delete preserves historical attribution.
- [x] Login identity notice and voice — Successful sign-in creates a user-specific Inbox notice and the browser announces the signed-in person's name, department and job title when speech is supported.
- [x] Formula report export — The Overview exports an Excel-compatible report containing daily rows and Daily/Weekly/Monthly/Yearly SUM formulas; existing authorized JSON/CSV import/export remains available in Administration.
- [x] Expense and profit register — Authorized business users can enter expense category, description, amount and payment method in a durable table. Overview calculates expenses and profit/loss from received income minus refunds and recorded expenses, with daily rows and Excel formulas.
- [x] Finance export/import — Finance screens provide an Excel-compatible expense report button, while Owner-only data management can export/import the expenses dataset as JSON and CSV exports include expenses.
- [x] Role capability toggle — Custom role creation/editing includes an on/off capability toggle for managing expenses and profit reports alongside catalog, users, audit, prices, notices and settings capabilities.
- [x] Service catalog safeguards — Service add/edit validates non-negative prices, disables save for invalid input, reports duplicate service names clearly, and retains an explicit Add service button.
- [x] Inactivity auto logout — Browser activity is tracked across pointer, keyboard, touch and scroll events. Heartbeats stop after 30 minutes without activity, the client logs out automatically, and the server rejects/deletes sessions whose last activity is at least 30 minutes old.
- [ ] POS checkout — A responsive POS sheet lets authorized staff select active products and services, adjust quantities, see the exact cart total, enter customer/payment details, mark payment received or pending, and create one itemized receipt using the existing audited receipt workflow.

- [x] Administration area grouping — The sidebar visibly groups administrative work under an Administration heading with Team accounts, Roles, Activity log, Permissions, Notices and Owner Settings, while server-side authorization remains authoritative.
- [x] Catalog add/change controls — Product, service and category tabs expose explicit Add buttons; products/services expose Edit price and active-state controls with validation and audit logging.
- [ ] GitHub and ZIP handoff — Preserve the canonical project checkpoint, create a source ZIP excluding dependencies/build output, and connect/push to the user’s authorized GitHub repository when the session’s GitHub connector permits it.
